# Task Routing

## Daily account review

Read the current daily workflow, state-reconstruction procedure, report contract, and any current executable mirrors named by those files. Reconstruct live account and market state, apply all data and control gates, and render the current daily product.

## Monthly funding review

Read the current monthly workflow, deployment framework, relevant Constitution files, and executable funding contract. Do not infer missing contribution, reserve, lifecycle, or executed-state inputs.

## Research request

Use for a proposed asset, indicator, strategy, exception, threshold, formula, or policy change. Route the proposal to the current Research process. Research output is not Production authority until the current approval and release process is complete.

## System audit

Inspect current HEAD, open changes, CI, release consistency, executable mirrors, policy drift, privacy controls, and operational readiness. Use live account state only when the audit explicitly includes a runtime production test.

## Repository changes

Immediately before writing, re-read current default-branch HEAD. Create a non-default branch, change only approved files, run current checks, push the branch, and open a pull request. Do not directly push or merge the protected default branch unless the account owner explicitly requests that exact action and repository governance permits it.
