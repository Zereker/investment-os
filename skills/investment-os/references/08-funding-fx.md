# 人民币资金准备与账户内换汇

本文件衔接已在 IBKR 内的投资资金与美元部署，政策范围以宪法为准。
不覆盖银行端跨境购汇，不增加投资标的，不做汇率预测。

## 1. 明确用途

用户可指定某笔已在账户内的 CNH 用于本袖套投资；这只是用途声明。
原币金额与结算事实必须从 IBKR 新鲜余额确认，不能用口述金额替代。
不保存每月额度，不从余额或单独换汇成交推断本月入金 F，不默认把全部 CNH 换成美元。
Daily 发现 CNH 时单独披露；月度资金审核读取本流程。

## 2. 准备换汇

读取新鲜账户、分币种余额、持仓和未完成订单，完成对账及借款检查。
从唯一 CNH 行读取现金和已结算现金，较小值只表示余额上限，不是换汇建议金额。
必须逐笔明确 CNH→USD、源币金额、保留的 CNH、报价方向、金额单位、
预计及最高可接受费用（含费用币种）、可用结算资金、是否有重复换汇或自动换汇。
任何金额连同各币种费用均不得使任何币种现金为负。不得用购买力代替余额。
报价、费用或相关自动化未知时，停止换汇执行，继续不依赖它的美元账户审核。
余额 exchange_rate 不可作为成交报价，也不可用它把 CNH 假定为 USD。

## 3. 能力与执行

先检查宿主实际提供的券商能力。股票、期权或期货下单接口不等于 CASH 换汇能力。
能力未提供时输出 `NOT EXECUTED`，由账户所有者在 IBKR 的货币转换界面检查
具体报价、费用、金额和结算提示后确认；agent 不生成不受支持的换汇订单。
如未来存在可验证的换汇接口，仍按 SKILL.md 的单次授权、提交一次、回读流程。
审批本流程不是对任何具体换汇金额或后续股票购买的授权。最终权限属于账户所有者，
当前会话无法验证其身份。换汇与买入是两个独立操作。

## 4. 换汇后验证

无论人工或工具执行，重新读取 IBKR 原币余额、已结算余额、未完成订单及成交证据。
预计金额、写入应答或人工完成声明均不能证明成交。证据不完整时输出
EXECUTION UNKNOWN 或 DATA INCOMPLETE，不重试、不重复换汇。
只有券商确认的已结算 USD 增量进入月度 C，费用影响以券商最终余额为准。
换汇后的市场、净值与持仓必须重新读取，不沿用换汇前快照计算部署。

## 5. 时间与下一观察条件

可在入金已结算后准备并逐笔确认换汇，不等待汇率信号。换汇不提前购买 ETF。
固定月度执行日使用当时已结算可用 USD；之后到账或结算的资金留到下个固定日。
不补算、不追溯改变本月次数；下一条件明确为 CNH 结算、换汇证据、USD 结算
或下一固定执行日，不写成笼统的“关注汇率”。

## 6. 报告

报告用途确认、源币与结算余额、换汇能力、费用与订单检查、授权范围、执行状态、
换汇后余额和下一观察条件。没有换汇时不将任何 USD 所得写成零或已结算。
真实账户快照与审核报告只在私有会话；必要的去重及成交回执按第 8 节进入可信私有存储，仓库仅保存规则和模拟测试。

## 7. 人民币定投资金确认路径

所有者约定新增投资资金仅以人民币进入账户。可逐期确认指定换汇成交对应新增
定投资金及分配期间；这是人工来源确认，不冒充券商独立证明外部入金。
本条明确例外于一般“人工声明不替代事实”规则：只允许确认资金来源、用途和
本期归属，金额、换汇成交、费用币种与结算状态仍须从新鲜 IBKR 能力核验。
不默认账户全部换汇均为新入金，不保存固定额度，不从余额差额推断 F。

指定 trade_ids，按 USD BUY、CNH 报价的 CASH 成交实际 USD 数量汇总；
扣除明确计费于 USD 的相关费用，CNH 费用不重复从 USD 所得扣除。
费用币种不明或结算未验证时 F 未知。现金余额提供可用资金上限，不证明来源。

分配期间必须明确。同一成交不得跨期或多次计入；先核验第 8 节的完整私有台账，
缺失或范围不完整不假定为空。审核、模拟不占用或消耗成交；真实执行前先保存
预占记录，成交回读后结算。历史已使用人民币或换汇不得追认新入金。
固定日之后结算的资金留到下个固定日，不补算。新路径与券商流水路径只能选一条，
不得重复相加；不改变 D、B、回撤公式或单笔授权边界。

## 8. 跨会话资金台账

台账不存公开仓库。每个账户使用单一可信台账，宿主验证台账与账户的关联及完整性，
不得换一个 ledger_id 清空历史。宿主必须有私有持久化存储，使用 ledger_id + revision
做原子 compare-and-swap 并回读，防止两个会话同时覆盖。没有此能力时明确只可
审核/模拟，关闭人民币路径真实定投执行，不声称已建立防重复保证。

funding_ledger 格式：schema_version=1、非空 ledger_id、整数 revision、
history_scope=verified_full_history、entries 列表。首次建立前须核验相关历史的
完整覆盖和既有使用情况；无法恢复时关闭路径，不因新建文件而默认空历史。
历史已使用的成交须导入条目；真实标识和金额不作公开示例。

每条含唯一 reservation_id、allocation_period、trade_ids、status：
reserved（已预占）、consumed（已使用）、partial（部分成交待核对）、released
（券商确认未执行且无未完成订单后释放）。前三种均阻止同一换汇成交再次作为 F。
已结算条目另含实际 dca_usd、broker_fill_ids；必须与券商用途关联证据核对，
台账不是当前余额、来源金额或授权的替代。部分成交须保留实际金额及成交关联，
剩余金额重新按券商和原用途核对，不把整笔换汇重新计入，也不自动跨期滚动。

helper 的 task=funding_ledger 只做内存转换，输入 funding_ledger、expected_revision、
change。预占 change：action=reserve、reservation_id、allocation_period、trade_ids。
结算 change：action=settle、reservation_id、receipt；receipt 含 status、dca_usd、
broker_fill_ids、broker_readback_verified、broker_orders_clear。两项布尔值只能由
真实券商成交及订单回读证据核验；计划仍有未完成订单时保持预占。
released 必须金额为 0、成交列表为空且相关订单已明确结束；未知结果仍保持 reserved。
helper 不验证券商接口来源，不代替 agent 的证据职责，不自动保存或重试。

执行顺序：新鲜月度计算通过 → 取得该笔操作授权 → 生成预占 → 原子保存并回读
新修订 → 再核验新鲜账户/订单和该次操作范围 → 提交一次 → 券商回读 → 生成结算
→ 原子保存并回读。多笔订单共享同一资金计划的预占，但每笔仍需独立授权；
计划未结束或有不确定订单时不结算为 released。结算前遇到部分成交可保留预占，
计划结束时记 partial 并保留全部成交关联；不得使用该预占再次计算一个新资金计划。
候选、测试、helper PASS 或保存成功均不是交易授权；存储失败或结果未知时停下
受影响执行，恢复后先查券商和台账，不重发订单。
