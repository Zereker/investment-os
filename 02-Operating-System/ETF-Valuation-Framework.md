# 三只 ETF 估值框架

本框架只覆盖 `SPYM / QQQM / SOXX`，回答“当前估值是便宜、合理、偏贵还是很贵，以及新增资金应如何处理”。它不扩大投资范围，不自动授权交易，也不以估值高低单独触发卖出。

## 1. 决策边界

- 当前价格用于账户计量和执行；价格回撤只辅助买入时点，不定义贵或便宜。
- Forward P/E 是主估值指标；每只 ETF 只与自己的历史比较，不用三只 ETF 的绝对 P/E 横向判定高低。
- 盈利增长、盈利预测修正和盈利收益率相对美国 10 年期国债的利差用于确认或否决，不单独制造“便宜”结论。
- SOXX 必须额外通过周期调整；仅有 Trailing P/E 时不得判定为便宜。
- 当前仓位、动态目标、现金和活动订单决定可执行金额；估值不能覆盖 Constitution、Alpha 生命周期或硬上限。

## 2. 生产数据口径

每只 ETF 至少记录：

- `last_price`、`observed_at` 与市场状态；
- `forward_pe`、官方/供应商标签、`source_as_of` 与来源；
- 同一指数、同一 Forward P/E 定义、同一来源的历史序列；
- `forward_pe_percentile`；
- `forward_eps_growth` 与三个月 `forward_eps_revision`；
- `earnings_yield_spread = 1 / forward_pe − US10Y`；
- 估值等级、确认状态、质量等级和受影响的执行路径。

历史窗口优先使用 10 年月末数据；若不足 10 年，至少需要连续 5 年、60 个互不重复的月末观察值。当前值不得参与历史分布构造，不得回填当时不可得的盈利预测。来源或定义变化时，必须重新建立可比序列，不能把不同口径直接拼接。

## 3. 基础估值等级

令 `p` 为当前 Forward P/E 在自身合格历史序列中的百分位，数值越高越贵：

| `p` | 基础等级 |
|---:|---|
| `p < 20` | `CHEAP` / 便宜 |
| `20 ≤ p < 70` | `FAIR` / 合理 |
| `70 ≤ p < 90` | `EXPENSIVE` / 偏贵 |
| `p ≥ 90` | `VERY EXPENSIVE` / 很贵 |

边界值按上表固定归档。若历史序列、当前 Forward P/E 或定义不可复现，等级为 `N/A / DATA INCOMPLETE`，不得用 Trailing P/E、截图或另一只 ETF 的估值代替。

## 4. 确认与保守调整

基础等级形成后，执行以下确认：

1. 盈利收益率利差与该 ETF 自身的同口径历史利差比较；当前利差处于历史低位时视为估值不利。
2. `forward_eps_growth > 0` 且三个月 `forward_eps_revision ≥ 0` 才算盈利支持；任一为负即不能把高 P/E 解释为已获盈利确认。
3. 两项确认同时不利时，最终等级保守上调一级；`VERY EXPENSIVE` 不再上调。
4. 确认结果混合、缺失或互相冲突时，不改善基础等级，并把置信度降为 `LOW / MIXED`。
5. 确认项只能维持或变得更保守，不能把基础等级下调为更便宜。

SOXX还必须满足：Forward P/E可得、未来盈利没有因周期低谷造成不可解释的基数失真、三个月预测修正可得。任一项缺失时不得输出`CHEAP`；若基础等级原为`CHEAP`，保守改为`FAIR / LOW CONFIDENCE`，其他等级只能维持或变得更保守。SOXX的`Frozen — DATA GATE`、阶段和执行上限始终优先于估值。

## 5. 新增资金动作映射

估值只改变新增资金节奏，不创造负缺口，也不覆盖现金下限：

| 最终等级 | SPYM / QQQM 新增资金动作 | SOXX |
|---|---|---|
| `CHEAP` | 执行 Routine DCA `D` 与战略基线 `B`；允许把额外加速 `T` 提交完整 IC | 仍按 Alpha / Data Gate；估值不构成追加授权 |
| `FAIR` | 执行 `D` 与 `B`；`T=0` | 同上 |
| `EXPENSIVE` | 只执行 Routine DCA `D`；`B` 与 `T` 暂缓，未用资金留在现金 | 同上 |
| `VERY EXPENSIVE` | 暂停该 ETF 的 `D / B / T`；资金流向另一只具有正缺口且合格的 Core，否则留在现金 | 同上 |
| `N/A / DATA INCOMPLETE` | 只允许 Routine DCA `D`；`B=T=0`，并报告缺失项 | 同上 |

当 SPYM 与 QQQM 的等级不同，先应用各自的资格，再按合格标的正缺口分配；估值不能让已超目标的 ETF 获得新增资金。估值等级为 `EXPENSIVE` 或 `VERY EXPENSIVE` 只减少或暂停新买入，不构成卖出理由。

## 6. 减仓规则

估值贵本身不能触发卖出。只有同时满足现行卖出条件——例如严重硬上限越界、Thesis 证伪、经审核替换，或税务/法律/流动性需要——才可形成 `SELL CANDIDATE`，并必须完成完整 IC。

## 7. 运行节奏

- 每日：读取实时价格、账户仓位、现金与订单；展示最近仍合格的估值等级及 `source_as_of`，不因日内价格重新计算历史序列。
- 每周：刷新三只 ETF 的 Forward P/E、盈利增长、预测修正和利率差。
- 每月执行前：重新计算历史百分位、确认项、最终等级和新增资金动作。
- 数据源、定义或历史序列变化：先通过独立 PR 更新 Data Registry；不得为了得到更有利的等级临时换源。
