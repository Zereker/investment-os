# 月度流程

月度流程是 Investment OS 的核心执行层，目标用时不超过 20 分钟。

## 输入

- 月末或定投日前的账户净值与持仓市值
- 本月净入金：默认 2,000 美元
- 当前税务或流动性约束
- 仍有效的 Alpha 名单
- SPYM 与 QQQM 的目标缺口
- 可验证的回撤和 PE 历史百分位数据

## 六步执行

1. 更新现金、SPYM、QQQM 和各 Alpha 的市值。
2. 计算当前权重、目标美元值与缺口。
3. 检查是否有资产越过允许区间或触发卖出规则。
4. 每月固定投入优先分配给最大正缺口。
5. 若要部署历史超额现金，必须执行 Deployment Framework；只看回撤不得加速部署。
6. 更新 Transition Dashboard，并在 Journal 记录非例行决定。

## 资金分配算法

- 目标美元值 = 调整后账户净值 × 目标权重。
- 正缺口 = max（目标美元值 − 当前市值，0）。
- 固定新增资金按正缺口比例分配；为减少碎片交易，可只购买缺口最大的 1–2 项。
- 超额现金不机械按缺口投入，而是同时比较 SPYM 与 QQQM 的回撤、估值、目标缺口和当前权重。
- Alpha 只有在季度审核仍为“保留/增加”且低于目标时才可获得资金。
- 没有合格 Alpha 时，Alpha 缺额暂时归入 SPYM，不进入新主题。

## 非例行部署记录

每次使用超额现金时，Journal 至少记录：

- 数据日期与来源；
- 当前价格和高点回撤；
- PE 数值、计算口径、历史窗口和百分位；
- Price / Valuation / Liquidity Score；
- 部署金额、订单类型和限价；
- 下一档触发条件；
- 交易后现金比例和 Core 权重。

## 完成条件

- 交易后现金仍在约束范围内，或按 Transition Plan 明确向范围靠拢。
- 没有未经审核的新标的。
- Dashboard 已更新。
- PE 数据冲突或口径不明时，没有以该数据触发战术交易。
- 无操作也是有效结果。

## Maintenance Mode

当全部资产连续三个自然月落在允许区间后，退出 Transition Mode。维护期继续执行同一流程，但不再主动部署历史超额现金；仅用每月新增资金修复偏差。
