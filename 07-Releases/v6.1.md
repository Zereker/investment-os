# Investment OS v6.1 — Agent Control Gate

## Release intent

v6.1 hardens the three-ETF Daily Brief MVP for multi-agent operation.

The release adds a portable execution contract that forces every agent to resolve fresh rules, reconstruct fresh broker state, declare sources and authority, and apply behavioral and procedural controls before producing a new purchase candidate.

The primary purpose is control replication, not convenience.

## What changed

- adds root-level `AGENTS.md` as the cross-agent execution contract;
- requires every formal decision output to declare repository commit, runtime sources, prior-agent material and approval status;
- makes prior-agent conclusions non-authoritative and explicitly non-transferable as approval;
- adds a Behavioral and Procedural Control Gate based only on observable process signals;
- defines an independent second-opinion protocol;
- requires authoritative position and order verification before new transaction candidates;
- defines a Journal single-writer model for concurrent agents;
- requires branch, checks, pull request and owner merge for repository changes;
- adds CI assertions that the agent contract contains procedure but no investment-policy parameters.

## Privacy

This release does not store personal trading incidents, dates, account values, orders, holdings or behavioral profiles.

Real events may motivate a control, but only the generalized control enters the public repository.

Manual figures and screenshots remain non-authoritative context. Current account state must be reconstructed from the broker sources required by Production.

## Policy impact

None.

v6.1 does not change:

- the current Production investment universe;
- target allocations or allowed ranges;
- cash and funding formulas;
- drawdown logic;
- tilt lifecycle rules;
- data-quality semantics;
- the human-only execution boundary.


Any future parameter change remains subject to the existing Research, approval, release and policy-consistency process.
