# Investment OS v6.3 — Alert Pointer Reliability Fix

## Purpose

v6.3 closes a state-synchronization gap in the broker-side drawdown alert pointer.

The defect shape was:

```text
new ATH detected
→ alert price recomputed from the new ATH
→ previous cycle tier identity survives
→ pointer can skip the first available tier of the new cycle
```

This release makes the expected pointer independently reproducible from current policy and reconstructed runtime state.

## What Changed

- Added `scripts/alert_pointer_check.py`.
- Added a daily expected-versus-actual alert pointer invariant.
- Made the new-ATH reset atomic across cycle state, executed-tier state and alert tier identity.
- Updated `State-Reconstruction.md` so broker alerts are actual state to verify, not the sole authority for executed tiers.
- Updated `Daily-Review.md` to require alert quantity, symbol, field, operator, tier and price checks.
- Added `BUG-023` to `BUGLOG.md`.
- Added CI self-tests for first-tier reset, next-tier progression, duplicate alerts and ladder exhaustion.

## Failure Behavior

When the actual alert does not match the expected pointer:

- Account Health is at least `WARN`;
- drawdown deployment state is `DATA INCOMPLETE`;
- no new drawdown deployment candidate is produced;
- the report states expected versus actual and the manual restoration condition;
- the agent does not create, modify or delete broker alerts.

Independent routine funding paths remain governed by their own Data Gates.

## Privacy

The repository stores only the generalized defect, invariant and synthetic tests.

It does not store:

- the user's alert identifier;
- the user's current ATH or alert price;
- account values, positions, orders or transaction history;
- a copy of the live broker alert state.

Runtime alert data remains ephemeral.

## Strategy Impact

None.

This release does not change:

- the investment universe;
- target allocations;
- drawdown triggers or tranche sizes;
- cash formulas;
- lifecycle rules;
- the human-only execution boundary.

It only verifies that the broker-side pointer mirrors the already published drawdown state machine.
