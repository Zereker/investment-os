# Investment OS v3.2 LTS — Production Hardening

发布日期：2026-07-30

> 勘误（2026-07-30）：后续全仓审计发现 Transition、Quarterly、Journal 与旧 Assistant 模板仍有现行 SPY / QQQ 或输出冲突，因此本版本的“全仓统一”验收并未完全成立。相关缺陷由 v3.3 修复；本文件保留为历史发布记录。

## 定位

v3.2 LTS 冻结 v3.2 的资产配置与 Deployment Score，不增加新的交易策略。本版本把已经确认的 IBKR 策略转化为可审计、可重复执行的生产系统。

## 生效内容

- 以 `PRODUCTION.md` 作为生产入口和执行契约。
- 固定 IBKR Account Summary → Balances → Positions → Open Orders 的读取顺序。
- 将 IBKR Positions 定义为当前持仓数量的权威来源。
- 数据不完整时统一降级为 `DATA INCOMPLETE / HOLD`，禁止用历史快照冒充实时状态。
- 所有真实资金候选必须通过 Trade Gate 和 Investment Committee Packet。
- 建立 Daily Review 与 Weekly Review；周度流程只汇总运行状态，不创造交易信号。
- 建立 `08-Data/` 数据注册表、字段字典、质量闸门和不可覆盖的快照。
- Production 与 Research 严格隔离；研究只有通过书面提案、明确批准和新版本发布后才能生效。
- 可靠性缺陷统一记录在 `BUGLOG.md`。

## 未改变

- Cash 15% / SPYM 42% / QQQM 28% / Alpha 15%。
- Alpha 合计与单只上限。
- 每月新增投入 2,000 美元。
- Valuation-Aware Deployment Framework 的评分区间和动作分档。
- Constitution 的卖出规则与年度治理窗口。

## 兼容性

这是 v3.2 的历史运行层，已由 v3.3 取代。旧版“六只阵型”“30% 现金红线”、斐波加仓位、每日盯单股和其他 Legacy Playbook 只保留为历史与行为教训，不再具有 Production 规则效力。

## 当时的验收标准

- 每次巡检能明确区分实时事实、计算、推断和建议。
- 任一关键数据失败都会关闭 Trade Gate。
- 非例行交易在下单前具有完整的四视角审查和明确 Verdict。
- 每周能发现数据、订单、行为或治理异常，同时不会因短期行情增加规则。
- 仓库内现行 Core 名称统一为 SPYM / QQQM（后续审计发现该项未完全达到，见顶部勘误）。
