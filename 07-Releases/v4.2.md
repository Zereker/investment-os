# Investment OS v4.2 — 估值子系统整体退役

发布日期：2026-08-01

## 主题

v4.2 删除整个估值子系统，把系统收敛为三条资金通道：Routine DCA `D`、Strategic Baseline `B`、Drawdown Deployment。三条全部由公式与价格驱动，**没有一条依赖拿不到的数据**。依据见 `Research/2026-08-01-valuation-subsystem-retirement.md`。

## 关键变化

1. **删除 `02-Operating-System/ETF-Valuation-Framework.md` 整篇**（87 行）。系统不再持有任何估值判断。
2. **退役 `T` 战术加速通道**。其准入条件是 `CHEAP`，随估值退役失去定义。资金通道由四条收为三条。
3. **取消 `VERY EXPENSIVE` 对 `B` 的暂停**。`B=min(S/R,G)` 完全决定基线，没有任何判断性闸门。
4. **价格职责收窄**：价格只用于计量、执行与回撤定档，不定义贵或便宜，不生成任何新增资格。
5. **数据层瘦身**：删除 7 行估值来源登记（三只 ETF 的 Forward P/E、历史百分位序列、EPS 增长/修正、US 10Y、Earnings Yield Spread）与约 36 行估值字段定义。

## 原因

- **四个输入字段全 Red 且无法转 Green。** 2026-08-01 实测：Invesco QQQM 官方页是纯 SPA，整页无任何 P/E 字样；iShares SOXX 官方页只能取到 **Trailing** P/E，而规则明令禁止用它判定便宜。
- **历史百分位是死结。** 基础等级完全依赖同口径 5–10 年月末序列，无源可得；即使今天开始逐月抬录也要到 2031 年才凑满 60 个观测。在此之前框架输出恒为 `N/A`——与 BUG-007、与 v4.1 修掉的 benchmark 日频模型是同一形态。
- **系统自己已否定过它。** v4.0 证据文档：「Forward P/E 历史百分位本身是弱择时工具，据此暂停新增有长期欠配风险。」
- **职能已被取代。** 回撤部署条款做同一件事，触发靠价格、零数据依赖，且已用 SPYM 十年真实收盘验证过状态机（七项不变量全部成立）。

## 明确的取舍

退役后失去「高位刹车」：即使市场处于极端估值，`B` 仍按计划迁移现金。但该刹车从未生效过——**今天不损失任何实际职能，损失的是一个名义上存在的选项**。

超出 `B` 的加速部署只剩回撤档位一条机械路径；主动加速须走「规则例外」的完整 IC。这更诚实：那本来就是例外，不是估值结论。

审判机制保留：SB-1 / SB-2 影子基准继续每月记录，年度审核必须回答「没有高位刹车是否付出了代价」。这是本决定的证伪路径。

## 复杂度账目

- 删除：框架 87 行、数据层约 43 行、CI 约 60 行估值机器、14 个文件中的散落条款。
- 新增：CI 对全部 active 文件的 5 项防复发 `forbid`（`CHEAP` / `VERY EXPENSIVE` / `Forward P/E` / `战术加速` / `ETF-Valuation-Framework`）。原「N/A 不得关闭 B」的 BUG-007 守护在无估值闸门后由构造保证，改由这组 forbid 承担。
- 净效果：显著净删除。

## 兼容性

**效果兼容**：被删的两条路径（`T`、`VERY EXPENSIVE` 暂停 `B`）从未产出过非 `N/A` 结论，退役不改变任何一次历史或未来的实际执行。文档层面是不兼容升级——v4.x 中所有估值相关表述全部失效。

未来若出现合格数据源，重新引入须走正常流程：`Research/` 提案 → 所有者批准 → 版本发布。退役不是永久禁令。
