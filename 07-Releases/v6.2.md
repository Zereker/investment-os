# v6.2 — Portable Investment OS Skill

## Status

Product and execution-layer release. No investment-policy parameters change.

## Purpose

v6.2 packages the existing repository execution discipline as a portable skill so different agents can run the same current policy against fresh broker state without embedding policy parameters or portfolio data.

The architecture is intentionally:

```text
thin skill + authoritative repository + fresh broker state
```

The skill is an execution and enforcement layer, not a second policy source.

## Added

- `skills/investment-os/SKILL.md`
- mandatory current default-branch HEAD resolution;
- exact commit provenance in formal outputs;
- task routing for daily review, monthly review, research requests, and system audits;
- fresh broker-state reconstruction requirements;
- source and authority declaration;
- cross-agent approval and behavioral/procedural controls through `AGENTS.md`;
- deterministic-tool preference and fail-closed behavior;
- repository-write and Journal boundaries;
- explicit privacy and completion standards.

## Parameter-Free Contract

The skill deliberately does not contain:

- production security identifiers;
- target allocations or ranges;
- drawdown levels or lifecycle stages;
- cash, reserve, or funding formulas;
- real account values or examples derived from them.

Every run must re-read the current repository HEAD. A policy change therefore requires only a repository release, not a synchronized skill parameter edit.

## Runtime Boundary

The skill requires live authoritative broker inputs for portfolio or transaction work. Manual figures, screenshots, pasted tables, old reports, and previous agent messages are context only and cannot authorize a transaction.

Missing or conflicting required inputs produce `DATA INCOMPLETE`; the skill does not fall back to memory.

## Multi-Agent Boundary

The skill applies the current `AGENTS.md` contract:

- no inherited approval;
- independent review is not created merely by switching agents;
- current positions and open orders are verified;
- observable bypass signals invoke the required control path;
- agents create Journal candidates, not concurrent durable Journal writes.

## Privacy

No personal trading history, account state, credentials, orders, values, quantities, or behavioral profile is stored in the skill or this release.

## Strategy Impact

None. v6.2 does not change the Production universe, target allocation, funding rules, drawdown rules, lifecycle rules, data-quality semantics, or human execution boundary.

## Validation

The product-contract check verifies that the skill:

- contains required routing and control language;
- contains no embedded production identifiers, percentages, policy formulas, tier labels, or hard-coded money;
- preserves the repository-as-authority and runtime-privacy contracts.
