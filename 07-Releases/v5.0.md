# Investment OS v5.0 — Decision System

## Release Type

产品化重构。**不改变 v4.6 的资产配置、SOXX 上限、回撤档位、资金公式或交易授权语义。**

## Why

v4.x 已形成成熟的政策、资金规则、数据门和计算镜像，但项目目标仍主要通过分散文档隐含表达。系统容易被理解为资产配置规则集合，而不是每天帮助账户所有者观察、理解、决策和监控的长期投资助手。

同时，公开仓库的隐私要求虽然已有局部检查，但尚未成为明确的产品契约：仓库应保存知识，个人组合状态只能存在于受信任的运行时。

## What Changed

### 1. Product Contract

新增 `PROJECT.md`，明确：

- Mission 与 Product Definition；
- 系统负责与不负责的事项；
- North Star；
- `Observe → Understand → Decide → Monitor → Repeat` 决策循环；
- 受控结论词表；
- 十项核心原则；
- 知识与状态分离；
- 公开仓库隐私边界；
- 所有未来变更的产品测试。

### 2. Daily Product Contract

新增 `02-Operating-System/Daily-Report-Contract.md`，把 `Investment Daily Report` 定义为主要日常产品，并固定：

- 前置数据条件；
- Executive Summary；
- Account Health；
- What Happened；
- Portfolio Allocation；
- Open Orders；
- Risk Check；
- Decision Eligibility；
- Production Decision；
- Attention Items；
- Next Observation Conditions；
- Fact / Interpretation / Decision / Monitor 分离；
- 隐私、留存与人工交易边界。

`HOLD` 被明确为正常且完整的产品结果，日报不以产生交易为成功标准。

### 3. Repository Entrypoint

README 重写为产品入口：先解释系统每天做什么和隐私边界，再呈现现行策略架构、生产原则和使用路径。

### 4. Product and Privacy CI

新增 `scripts/check_product_contract.py`，检查：

- 产品契约关键原则存在；
- 日报契约关键章节存在；
- README 正确链接产品入口；
- 常见运行时账户数据文件和目录不得进入公开仓库。

GitHub Actions 在原有政策一致性检查后运行该检查。

## Privacy Contract

> Repository stores knowledge, never portfolio.

以下真实信息不得进入公开仓库、Issue、PR、日志、fixture、截图或快照：账户标识、NAV、现金金额、持仓市值、股数、成本、订单、成交、入金、收益、税务和可反推出个人资产的信息。

测试只允许使用明确标记且不可反推真实账户的 synthetic 数据。

## Compatibility

v5.0 不改变：

- 现金 15% 目标与常态区间；
- QQQM 28% 目标；
- SPYM 动态目标；
- SOXX 6% 永久硬上限与当前 3% 执行上限；
- SOXX 回补与提高倾斜的双路径；
- 四档回撤部署；
- Data Gate；
- 人工下单边界；
- 现有月度计算器和回撤状态机。

## Acceptance Criteria

- `python3 scripts/check_policy_consistency.py` 通过；
- `python3 scripts/check_product_contract.py` 通过；
- README、PROJECT、Daily Report Contract 和本发布说明相互一致；
- PR 不包含任何真实账户状态；
- diff 不引入新的投资参数或交易授权语义。
